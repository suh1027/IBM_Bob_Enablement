# IBM Bob Hands-on Lab 03

# 간단한 웹사이트 구성

> 
> 
> 
> 지금까지 학습한 Bob의 Plan과 Agent 기능을 활용하여 간단한 웹사이트를 직접 구성합니다.
> 
> 이번 Lab에서는 정해진 구현 방법을 제공하지 않습니다.
> 
> 요구사항을 해석하고, Plan을 작성하고, 구현 방법을 결정하는 과정까지 Bob과 함께 자유롭게 진행합니다.
> 

### 실습 목표

이번 Lab에서는 간단한 **회원가입(Sign Up) 페이지**를 만들어봅니다.

최종 결과보다 다음 개발 흐름을 직접 경험하는 것이 목적입니다.

```
Requirement
    ↓
Plan
(create-plan Skill)
    ↓
Plan 확인 / 수정
    ↓
Agent
    ↓
Implementation
    ↓
Browser Check
    ↓
필요 시 추가 개선
```

---

# 1. 요구사항 확인

아래는 이번 Lab의 최소 요구사항입니다.

### 회원가입 페이지

페이지에는 다음 항목이 포함되어야 합니다.

```
회원가입 페이지

이름
이메일
비밀번호
비밀번호 확인

[ Sign Up ]
```

기본적으로 다음 기능도 구현합니다.

```
□ 필수 입력값 확인

□ 이메일 형식 확인

□ 비밀번호와 비밀번호 확인 값 비교

□ 정상 입력 시 가입 완료 메시지 표시

□ Mobile에서도 사용할 수 있는 Layout
```

실제 회원정보 저장이나 Backend 연결은 수행하지 않습니다.

```
HTML / CSS / JavaScript
        ○

Backend
        ✕

Database
        ✕

실제 회원가입 API
        ✕
```

# 2. Plan Mode — 구현 방법 계획하기

바로 코드를 생성하지 않고 먼저 **Plan Mode**로 전환합니다.

Bob의 Plan Mode는 계획 수립 시 `create-plan` Skill을 활용하여 요구사항과 현재 프로젝트 Context를 조사하고 구현 계획을 작성합니다. 필요하면 Explore Subagent를 활용하여 프로젝트 구조를 추가로 조사할 수도 있습니다.

### 예시 Prompt

```
간단한 회원가입 웹페이지를 만들려고 해.

다음 기능이 필요해.

- 이름 입력
- 이메일 입력
- 비밀번호 입력
- 비밀번호 확인
- Sign Up 버튼
- 필수 입력값 Validation
- 이메일 형식 Validation
- 비밀번호 일치 여부 확인
- 정상 입력 시 회원가입 완료 메시지 표시
- Responsive Layout

Backend와 Database는 사용하지 않을 거야.

HTML / CSS / JavaScript만 사용해서
간단하게 구현하고 싶어.

create-plan Skill을 활용해서
구현 계획을 작성해줘.

계획에는 다음 내용을 포함해줘.

1. 필요한 파일
2. 페이지 구조
3. 주요 UI 구성
4. JavaScript 기능
5. Validation 방법
6. 구현 순서
7. 완료 후 확인할 항목

아직 코드는 작성하지 마.
```

---

## Plan 작성 과정 살펴보기

Plan Mode에서는 Bob이 Skill 또는 Subagent 사용 승인을 요청할 수 있습니다.

```
Plan Mode
    ↓
create-plan Skill
    ↓
Context 확인
    ↓
필요 시 Explore Subagent
    ↓
Implementation Plan
```

Permission이 표시된다면 어떤 Tool을 사용하려는지 확인한 뒤 승인합니다.

# 3. 만들어진 Plan 확인

Bob이 작성한 계획을 살펴봅니다.

예를 들어 다음과 같은 구조를 제안할 수 있습니다.

```
signup/
├── index.html
├── styles.css
└── script.js
```

또는 하나의 파일로 단순하게:

```
signup.html
```

을 제안할 수도 있습니다.

**둘 다 정답입니다.**

이번 Lab에서는 참가자가 원하는 방식을 선택합니다.

---

## Plan을 그대로 사용할 필요는 없습니다

Bob의 계획을 보고 원하는 방향으로 변경해도 됩니다.

예를 들어:

```
파일을 여러 개 만들지 말고
signup.html 하나로 간단하게 구현하고 싶어.

Plan을 그 기준으로 수정해줘.
```

또는:

```
회원가입 Form 아래에
이미 계정이 있는 사용자를 위한
"Sign in" 링크도 추가하고 싶어.

Plan에 반영해줘.
```

처럼 요구사항을 변경할 수 있습니다.

### 핵심

```
Bob Plan
   ↓
개발자 확인
   ↓
요구사항 수정
   ↓
Plan 보완
   ↓
구현
```

# 4. Agent Mode — 계획 구현하기

Plan이 적절하다면 **Agent Mode**로 전환합니다.

Bob 공식 튜토리얼에서도 계획을 완료한 후 새로운 Context에서 Agent Mode로 전환하여 승인된 Plan을 구현하도록 안내합니다.

### 간단한 Prompt

```
방금 작성한 회원가입 페이지 Plan을
기준으로 실제로 구현해줘.

Plan에서 정의한 범위만 구현하고
불필요한 Framework나 Package는 추가하지 마.

구현 완료 후

1. 생성한 파일
2. 구현한 기능
3. 테스트해야 할 항목

을 알려줘.
```

이후 Bob이 파일 생성을 요청하면 변경 내용을 확인하고 승인합니다.

# 5. 웹페이지 직접 확인

구현이 완료되면 생성된 HTML 파일을 브라우저에서 실행합니다.

다음 정도만 확인합니다.

```
□ 회원가입 화면이 정상적으로 표시되는가?

□ 이름을 입력할 수 있는가?

□ 이메일을 입력할 수 있는가?

□ 비밀번호를 입력할 수 있는가?

□ 필수 항목을 비우면 Validation이 동작하는가?

□ 이메일 형식이 잘못되면 안내가 표시되는가?

□ 두 비밀번호가 다르면 안내가 표시되는가?

□ 정상 입력 시 완료 메시지가 표시되는가?

□ 작은 화면에서도 Layout이 깨지지 않는가?
```

# 6. 여기부터는 자유롭게 개선해보기

기본 회원가입 페이지가 완성되었다면 남은 시간에는 원하는 방향으로 자유롭게 발전시켜봅니다.

정해진 순서는 없습니다.

### 예시 아이디어

- Password 표시/숨김 기능 추가
- Password 강도 표시
- 약관 동의 Checkbox 추가
- 이름을 First Name / Last Name으로 분리
- Dark Mode 추가
- Login 페이지 추가
- 가입 완료 화면 추가
- Validation Message 디자인 개선
- Accessibility 개선
- `html-validate`를 이용한 코드 검증
- 별도의 Skill을 만들어 반복 작업에 적용

원하는 기능을 Bob에게 직접 설명하고 어떻게 구현할지 계획해봅니다.

예:

```
현재 회원가입 페이지에
비밀번호 표시 / 숨김 기능을 추가하고 싶어.

기존 디자인은 유지하고
변경해야 할 영역을 먼저 분석해줘.
```

또는:

```
현재 회원가입 페이지를
조금 더 기업용 서비스 같은 디자인으로 바꾸고 싶어.

먼저 개선 방향을 제안해줘.
아직 코드는 수정하지 마.
```

# 7. 선택 과제 — Bob 활용 방식을 바꿔보기

같은 기능이라도 Bob을 사용하는 방법은 여러 가지입니다.

이번 Lab에서는 남은 시간이 있다면 다양한 방법을 자유롭게 시도해봅니다.

```
Plan Mode
→ create-plan Skill로 계획부터 작성

Ask Mode
→ 현재 코드나 구현 방법 질문

Agent Mode
→ 실제 파일 생성 및 수정

Skills
→ 반복적인 개발 방법을 Skill로 정의

Subagent
→ 필요할 경우 별도 Context에서 코드나 구조 탐색
```

Skills는 반복 가능한 작업 방법을 `SKILL.md`로 정의하여 Bob이 일관된 방식으로 수행하도록 만드는 기능입니다. 직접 Skill을 호출하거나, Skill의 설명을 바탕으로 Bob이 자동으로 선택할 수도 있습니다.
